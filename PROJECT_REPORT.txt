            PARTIE 2 : EXPLICATION DU FICHIER DOCKER-COMPOSE.STAGING.YML

DESCRIPTION GÉNÉRALE
====================
Ce fichier Docker Compose configure l'environnement de STAGING pour TalentPredict.
Il orchestre 3 services conteneurisés :
• PostgreSQL (Base de données)
• Backend Spring Boot (API REST)
• Frontend Angular + Nginx (Interface utilisateur)

Version Docker Compose : 3.8


ARCHITECTURE DES SERVICES
==========================

┌─────────────────────────────────────────────────────────────┐
│                    ENVIRONNEMENT STAGING                     │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐  │
│  │   Frontend   │───▶│   Backend    │───▶│  PostgreSQL  │  │
│  │   (Nginx)    │    │ (Spring Boot)│    │  (Database)  │  │
│  │   Port: 80   │    │  Port: 8081  │    │  Port: 5433  │  │
│  └──────────────┘    └──────────────┘    └──────────────┘  │
│                                                              │
│          Réseau: talentpredict-staging (bridge)             │
└─────────────────────────────────────────────────────────────┘


SERVICE 1 : POSTGRESQL DATABASE (postgres-staging)
===================================================

Configuration de base :
• Image : postgres:16-alpine (version légère)
• Container : talentpredict-postgres-staging
• Restart : unless-stopped (redémarre automatiquement)

Variables d'environnement :
• POSTGRES_DB : talentpredict_staging
• POSTGRES_USER : ${STAGING_DB_USER:-postgres}
• POSTGRES_PASSWORD : ${STAGING_DB_PASSWORD}

Volumes (Persistance) :
• postgres_staging_data:/var/lib/postgresql/data
  → Les données survivent même si le conteneur est supprimé

Ports :
• 5433:5432 (Port hôte:Port conteneur)
  → Port différent de dev (5432) pour éviter les conflits

Health Check :
• Commande : pg_isready -U postgres -d talentpredict_staging
• Interval : 10 secondes
• Timeout : 5 secondes
• Retries : 5 tentatives
• Start period : 30 secondes (délai initial)
  → Vérifie que la base de données est prête avant de démarrer le backend

Limites de ressources :
• Memory limit : 512 Mo
• Memory reservation : 256 Mo


SERVICE 2 : BACKEND SPRING BOOT (backend)
==========================================

Configuration de base :
• Image : ${CI_REGISTRY_IMAGE}/backend:${BACKEND_TAG:-latest}
• Container : talentpredict-backend-staging
• Restart : unless-stopped

Variables d'environnement :
• SPRING_PROFILES_ACTIVE : staging
  → Active le profil application-staging.properties
• SPRING_DATASOURCE_URL : jdbc:postgresql://postgres-staging:5432/...
  → Connexion à la base via le nom DNS du service
• SPRING_DATASOURCE_USERNAME : ${STAGING_DB_USER:-postgres}
• SPRING_DATASOURCE_PASSWORD : ${STAGING_DB_PASSWORD}
• JWT_SECRET : ${STAGING_JWT_SECRET}
  → Secret pour la génération des tokens JWT
• SERVER_PORT : 8081
• JAVA_OPTS : 
  - -XX:+UseContainerSupport (optimisation conteneur)
  - -XX:MaxRAMPercentage=75.0 (utilise max 75% de la RAM allouée)
  - -XX:+UseG1GC (Garbage Collector G1, performant)

Ports :
• 8081:8081
  → Port différent de dev (8080) et prod (8082)

Dépendances :
• depends_on postgres-staging avec condition service_healthy
  → Attend que PostgreSQL soit "healthy" avant de démarrer
  → Évite les erreurs de connexion DB au démarrage

Health Check :
• Endpoint : http://localhost:8081/actuator/health
  → Utilise Spring Boot Actuator pour vérifier l'état
• Interval : 30 secondes
• Timeout : 10 secondes
• Retries : 5 tentatives
• Start period : 60 secondes (Spring Boot prend du temps à démarrer)

Limites de ressources :
• Memory limit : 1 Go
• Memory reservation : 512 Mo

Logs :
• Driver : json-file
• Max size : 10 Mo par fichier
• Max files : 3 fichiers
  → Rotation automatique, max 30 Mo de logs


SERVICE 3 : FRONTEND ANGULAR + NGINX (frontend)
================================================

Configuration de base :
• Image : ${CI_REGISTRY_IMAGE}/frontend:${FRONTEND_TAG:-latest}
• Container : talentpredict-frontend-staging
• Restart : unless-stopped

Ports :
• 80:80
  → Port HTTP standard, point d'entrée de l'application

Dépendances :
• depends_on backend
  → Démarre après le backend (pas de health check strict)

Health Check :
• Endpoint : http://localhost/
  → Vérifie que Nginx répond
• Interval : 30 secondes
• Timeout : 5 secondes
• Retries : 3 tentatives

Limites de ressources :
• Memory limit : 256 Mo (Nginx est léger)
• Memory reservation : 128 Mo

Logs :
• Driver : json-file
• Max size : 10 Mo par fichier
• Max files : 3 fichiers


NETWORKS (RÉSEAU)
=================

talentpredict-staging :
• Driver : bridge
  → Réseau isolé pour ces 3 conteneurs
• Isolation : Les services communiquent entre eux mais sont isolés 
              des autres environnements
• DNS interne : Chaque service est accessible par son nom
  - postgres-staging → Base de données
  - backend → API
  - frontend → Interface web


VOLUMES (STOCKAGE PERSISTANT)
==============================

postgres_staging_data :
• Nom : talentpredict-postgres-staging-data
• Fonction : Stockage persistant pour PostgreSQL
• Persistance : Les données restent même si on supprime les conteneurs
• Isolation : Volume nommé séparé de dev et prod


FLUX DE DÉMARRAGE
=================

1. Création du réseau talentpredict-staging
2. Création du volume postgres_staging_data
3. Démarrage PostgreSQL → Health check (30s)
4. Attente que PostgreSQL soit healthy
5. Démarrage Backend Spring Boot → Health check (60s)
6. Démarrage Frontend Nginx
7. Application accessible sur http://localhost


VARIABLES D'ENVIRONNEMENT REQUISES
===================================

À définir dans un fichier .env ou dans le CI/CD :

STAGING_DB_USER=postgres
STAGING_DB_PASSWORD=your_secure_password
STAGING_JWT_SECRET=your_jwt_secret_key
CI_REGISTRY_IMAGE=registry.gitlab.com/your-project
BACKEND_TAG=staging-v1.2.3
FRONTEND_TAG=staging-v1.2.3
